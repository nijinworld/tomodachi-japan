# 開発の分担 ｜ 複数のセッションで並行して進めるとき

**新しいチャットを開いたら、このファイルと `docs/エンジニア引き継ぎ書.md` を先に読ませてください。**
それだけで、自分の担当と、触ってはいけないものが分かるようにしてあります。

---

## 分け方は「機能」ではなく「ファイルの所有権」

機能で分けると、全員が `server/routes/api.js` と `web/app.js` を触ることになり、必ず衝突します。
この2つは全機能が通る場所なので、**編集できるのは常に1本だけ**です。

| 担当 | 触ってよいファイル | 同時に何本 |
|---|---|---|
| **中核** | `server/routes/api.js`／`server/index.js`／`web/*`／`scripts/*` | **1本だけ** |
| **ライブラリ** | `server/lib/` に**新規1ファイル** ＋ 対応する `test/<名前>.test.js` | 2〜3本 |
| **レビュー** | **編集しない**（読むだけ） | 1〜2本 |
| **仕様・文書** | `docs/*.md`（`spec/` は下の注意） | 1本 |
| **データ・テスト** | `scripts/seed.js`／`test/run.js` | 1本 |

現実的な上限は **中核1本＋並行3本**。それ以上は中核が統合待ちのボトルネックになります。

## 並行させるときの決めごと

### 1. モデル版に触るファイルは、中核が単独で扱う

`spec/rubric.ja.json` と `prompts/feedback.ja.md` は**モデル版の指紋に入ります**。
変えたら再凍結（`node scripts/freeze-model.js`）と全授業の再スコアが要ります。
他のセッションが黙って直すと、スコアが版をまたいで混ざり、12月のA/Bが成立しません。

### 2. データディレクトリを分ける

```bash
RANIUS_DATA_DIR=/tmp/work1 node ...
```

`data/` を共有したまま `node scripts/seed.js` を走らせると、もう片方のデータが消えます。
**並行セッションに `seed.js` を実行させないでください。**

### 3. ポートを分ける

`PORT=5182 node server/index.js` のように。同じ 5173 で起動すると `EADDRINUSE` で静かに死に、
**古いサーバが生き残って「直したのに反映されない」ように見えます**。

サーバはメモリにデータを載せています。`seed.js` やファイルを直したあとは必ず再起動してください。

### 4. ライブラリ担当には、関数の形を先に渡す

```
parse(text, opts) → { utterances, speakers, format, warnings }
```

ここまで決めて投げると、そのまま統合できます。決めずに投げると設計から始まるので遅くなります。

### 5. レビュー担当には編集させない

編集権を持たせると中核と衝突します。**指摘だけ受け取り、中核が直す**ほうが速い。
これまでの実績：権限の穴を10件、うち7件が本物でした。

### 6. 終わりに必ずテスト

```bash
npm test
```

いま108件あります。ライブラリ担当は自分のテストファイルも通ること。

### 7. Google Drive の同期に注意

このフォルダは Drive 上にあります。**同じファイルを2つのセッションが書くと `(1)` 付きの複製が生まれます。**
実際に何度も起きました。見つけたら中身を確認し、古いほうを `07_アーカイブ/` に移してください。

## 新しいセッションに渡すテンプレート

```
日本語で作業してください。

## 対象
G:\マイドライブ\01_Ranius\03_プロダクト\ranius-nihongo\
Node.js、依存パッケージゼロ、CommonJS。

## 並行作業のルール（他のセッションが同時に動いています）
- 新規2ファイルだけを作る：server/lib/<名前>.js と test/<名前>.test.js
- server/routes/api.js、web/*、server/index.js、test/run.js、spec/*、prompts/* は絶対に触らない
- data/ を書き換えるコマンド（scripts/seed.js など）は実行しない。読むだけなら可
- サーバを起動するなら PORT=518x
- 最後に node test/<名前>.test.js が通ることを確認する

## まず読むもの
docs/エンジニア引き継ぎ書.md の 3章と5章（破ってはいけない約束）
server/lib/ の既存ファイル（書き方と語り口を合わせる）

## つくるもの
<関数のシグネチャをここに書く>

## 必ず守ること
- 先生の順位をつけない。比較対象は本人の過去だけ
- 人格に触れる語を出力に入れない（server/lib/ja.js の findPersonalityTerms で自己検査）
- 未測定と 0 を混ぜない
- Math.random() / Date.now() / 引数なし new Date() を使わない（再現性が最優先）
- store を require しない（データは引数で受け取る）
- コメントは日本語。既存ファイルと同じ密度で「なぜそうしているか」を書く
```

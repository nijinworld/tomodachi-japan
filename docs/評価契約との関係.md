# NIJIN 評価契約との関係

このシステムは、Ranius プラットフォーム（`nijinworld/ranius-platform`）の評価契約と、
**同じ形で結果を出せる**ようにしてあります。ただし観察のしかたが違います。
その違いを、ここに正直に書いておきます。

---

## 1. どこが同じで、どこが違うか

| | Ranius プラットフォーム | ともだちじゃぱん（このシステム） |
|---|---|---|
| 観察するもの | **授業の映像**（Gemini が見る） | **書き起こしのテキスト**（決定的な計算） |
| 観察の再現性 | temperature 0.1・seed なし。**同じ動画から同じ結果は出ない** | **同じ書き起こしから必ず同じ結果が出る** |
| 変換（観察→点） | 決定的 | 決定的 |
| ルーブリック | `nijin-core-1.0.0`（5軸） | `nijin-nihongo-1.0.0`（5軸。2軸はキーを共有） |
| 費用 | 30分授業で約 $0.61 | ほぼゼロ（LLMを呼ばない） |
| 見えないもの | — | 表情、カメラ、チャット、成果物 |

**両方が要ります。** 映像でしか見えないものがあり、再現性はテキストでしか出せません。

---

## 2. 軸の対応

| ともだちじゃぱん | 重み | nijin-core での位置 |
|---|---:|---|
| 安心して日本語を出せる | 25 | **同じキー**（`psychological_safety_and_participation_choice`） |
| わかる高さに合わせる | 20 | 新規。第二言語の授業でしか見えない |
| 通じないときに、通じさせる | 20 | 新規。`dialogic_co_construction` を言語のやりとりに分けたもの |
| 訂正が届いたか | 20 | 新規。同上 |
| 言えることが増えたか | 15 | **同じキー**（`output_quality_and_transformation`） |

**外した2軸**：`productive_departure_and_response`（予定調和からの逸脱）、`concrete_abstract_cycle`（具体と抽象の往還）。
日本語の授業に当てはめにくいため、採点軸から外しました。観察資料としては残します。

**キーを2つ共有しているのは意図的です。** 版が違っても、この2軸だけは比較できます。

---

## 3. 正面からぶつかっていた1点

向こうの不変条件5はこうです。

> **顔出し率、発話比率、チャット数等の `measurement` は採点関数へ入力しない。**

一方、このシステムの `server/lib/scoring.js` は、**モーラ数・ジニ係数・待ち時間から直接スコアを出しています**。
これは向こうの契約と正面からぶつかります。

`server/lib/contract.js` を通すと、この矛盾が解けます。

- 発話量の観点（TD）は**軸から外れ**、`measurement` に落ちます
- 発話比を大きく変えても、**軸の判定は動きません**（テストで固定してあります）
- 残る4軸は、行動の観察（言い直し・聞き返し・待ち時間・長い発話）を根拠にします

**なぜ向こうが正しいか。** 発話量を得点にすると、先生はそこを操作しにいきます。
「たくさん話させれば点が上がる」と分かった瞬間に、その数字は指標として死にます。

**なぜこちらも要るか。** 事業計画は「モデルを凍結して、IRR .65 を出して、AEA に事前登録する」と書いています。
観察がぶれると、この3つが成立しません。**再現できない器具では、一致も測れません。**

## 4. 契約を通すと、何が起きるか

デモの授業1本を `contract.evaluate()` に通した結果です。

```
状態: needs_review    総合点: null

  review_required   安心して日本語を出せる           level null  conf 0.5
  review_required   わかる高さに合わせる             level null  conf 0.6
  scored            通じないときに、通じさせる        level 5     conf 0.75
  review_required   訂正が届いたか                   level null  conf 0.6
  not_observable    言えることが増えたか             level null  conf 0
```

**5軸のうち4軸が未確定で、総合点が出ません。**

同じ授業を、このシステムの画面は「5観点の平均 3.1／4」と表示します。
どちらが嘘かというと、**画面のほうが言い過ぎています**。

理由は3つです。

1. **リキャストと取り込みの検出は、文字の重なりからの推定**です。確からしさを 0.6 と置きました。0.65 未満なので、その軸は自動確定しません
2. **根拠が2場面ぶん揃わない**軸があります（契約は「離れた2場面、または完結した1連鎖」を要求します）
3. **アウトプットの軸は人間評定が主**なので、こちらからは候補を出しません

これは不具合ではなく、**契約が意図どおり働いた結果**です。
`00_はじめに/03_まだ証明していないこと.md` の「検証済みと未検証を混ぜない」を、
コードのレベルで実行するとこうなります。

---

## 5. これをどう使うか

- **12月のA/Bまで**：画面の 0〜4 表示は、現場の振り返り用として残す。
  ただし**対外説明には契約を通した結果を使う**（総合点が出ないなら、出ないと言う）
- **IRR を測るとき**：契約の `dimension_candidates` を、人間の評定と突き合わせる。
  向こうのゴールドセット形式（`double_labeled` → `adjudicated_gold`）に合わせられます
- **精度を上げるとき**：リキャストと取り込みの検出を形態素解析に置き換えれば、
  確からしさが 0.6 から上がり、自動確定できる軸が増えます。**モデル版が変わるので再スコアが要ります**

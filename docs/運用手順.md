# 運用手順 ｜ 現場でやること

対象：伊佐・青田（講師採用・育成）、メンター、ファシリテーター、外部評定者
読む時間：10分。**自分の役割の章だけでいいです。**

---

## 0. ログイン

http://localhost:5173 を開き、**自分のユーザーIDまたは名前**と**合言葉**を入れます。

- 合言葉は運営から口頭で受け取り、**初回ログイン後に自分で変えてください**（左下「合言葉を変更」）
- 12時間で切れます。切れたら入り直してください
- **共有の端末では、使い終わったら必ずログアウト**（左下）。子どもの発話が入っています

見える範囲はロールごとに違います。「自分に見えないもの」は、権限がないのではなく、
**見えないことに意味がある**設計です（とくに外部評定者）。

---

## 1. メンターがやること（毎日1行）

**これが、この事業でいちばん大事な作業です。** 機能ではなく、この1行が事業計画の全論拠です。

1. `#/mentor` を開く
2. 誰に・何分・何をしたか、を入れる（授業を見た／所見を返した／チーム会／その他）
3. それだけ

### よくある間違い

| ❌ | ⭕ |
|---|---|
| 週末にまとめて「たぶん30分くらい」で入れる | その日のうちに、実際にかけた分数を入れる |
| 短い時間は面倒だから入れない | 5分でも入れる。**分母が小さいほど担当数が大きく見えてしまう** |
| 所見をシステム外（チャット）で返して記録しない | 所見はシステムに書く。時間も一緒に記録される |

> **「だいたい」で入れた数字は、12月に使えません。**
> メンター単価は、この事業がSFで話す唯一の新しい数字です。

---

## 2. IRR（評価者間一致）を測る ／ 10月20日まで

**目標 .65。** これ未満なら、ルーブリックが機能していないということです。

### 手順

1. 外部評定者を **2名** 確保する（社内の人でもよいが、その先生を知らない人）
2. その2人に **rater ロールのアカウント**を作る（運営が「人とクラス」から作成し、合言葉を渡す）
3. 評定者はログインすると **「盲検の採点」しか出ません**。
   先生の名前・アーム・AIのスコア・子どもの名前は、システムが**見せません**
4. キューの上から採点する。**「もう1人ぶん待ち」**が付いている授業を優先すると、ペアが早く揃います
5. 見るのは **冒頭15分だけ**。全部見なくていい（信頼性の6割が出る）
6. 運営が `#/irr` で二次重みつきカッパを見る

> **評定者に「この先生は〜」と伝えないでください。** 口頭で漏れたら、その授業のペアは使えません。

### 出た数字の読み方

| QWK | 意味 | 次にやること |
|---|---|---|
| .65 以上 | 器具として使える | 妥当性（何を測っているか）の検討へ |
| .50〜.65 | 惜しい | ルーブリックの**記述語**を直す。計算式ではない |
| .50 未満 | 観点の意味が2人で違う | 観点を減らすか、書き直す |

**直すのは記述語です。** スコアの計算式をいじって一致を上げるのは、器具ではなく採点者を歪めることです。

## 2.4 取り込む前に：保護者の同意

**同意のない子どもが名簿にいるクラスは、書き起こしを取り込めません。**
取り込もうとすると、その子の名前を出して止まります。これは仕様です。

1. 配布と説明は `docs/保護者への説明.md` のひな型を使う（【　】を自校の内容に置き換える）
2. 同意をもらったら `#/people`（人とクラス）でその子の「記録」を押す
3. 誰から・いつ・どの方法で、を入れる

撤回のご連絡を受けたら、画面で撤回を記録し、
`node scripts/purge.js --student <その子のID>` を実行してから、ご家庭に「消しました」と伝えてください。
**実行する前に「消しました」と言わないでください。**

---

## 2.5 授業の書き起こしを取り込む

1. Zoom / Google Meet / Teams の書き起こしをコピーする（VTT・SRT・CSVのファイル中身でも可）
2. `#/import`（書き起こしの取り込み）を開く
3. クラスと日付を選び、テキストを貼って「読み込む」
4. **話者を対応づける** — いちばん話している人が先生として初期選択されます。違ったら直してください
   - 対応づけない話者（見学者など）は「取り込まない」のままに
   - ここで選んだ**子どもの名前は保存されません**。クラスの子どもに紐づくだけです
5. 「この内容で授業をつくる」→ そのまま採点され、所見まで出ます

読めなかった行があれば、件数と中身が出ます。全部読めなくても止まりません。

## 3. 子どものアンケート（隔週）

効果 **d=0.27**。ただし **返し方の設計が効果のほぼ全部**です（設計あり 0.568／なし 0.050）。

### 守ること（全部やって初めて効きます）

1. **頻度で聞く**（「いつも／よくある／ときどき…」）。「そう思う／思わない」では効きません
2. **主語は「わたし」**。「先生は〜」ではなく「わたしは〜」
3. **1観点につき複数項目**で聞く
4. 先生に返したら、**チームの週次で次の1手を1つ宣言する**
5. **子どもに「みんなの答えを見て、次はこうします」と伝える**

4と5を飛ばした回は、システムが「設計なし」として記録します。責めるためではなく、
**あとで「効いた回」と「効かなかった回」を分けるため**です。

### 配り方

1. 運営かメンターが `#/surveys` で、クラスと回（例：2026-C1）を選んで**配布リンク**を作ります
2. そのリンクを子ども（または保護者）に渡します。**ログインは要りません**
3. 子どもはスマホでも開けます。12問、頻度で選ぶだけです
4. 締め切ったらリンクを閉じます

**誰が何と答えたかは、システムにも残りません。** 回答に子どものIDを保存していないためです。
「先生に知られる」と思われた瞬間に、この仕組みは死にます。

### 回答が3件以下のとき

集計は返しません。誰が書いたか割れてしまうためです。

## 4. ファシリテーターがやること

### 授業のあと

1. `#/facilitator/自分` を開く
2. AIの所見を読む。**書いてあるのは、時刻と、起きたことだけ**です
3. 「次の1手」は1つだけ書いてあります。**やるかどうかは自分で決めます**

### 週次のチーム（4〜8名）

1. 自分の所見から、次の1週間でやることを **1つだけ** 選ぶ
2. チームで宣言する
3. 次の週、できたかどうかを本人が判定する

> **3つ選ぶと、0個実行されます。** 1つにしてください。

### 見なくていいもの

- 他の先生のスコア（システムに出せません）
- 平均・順位（作っていません）

**比較対象は、あなたの過去だけです。**

## 5. アーカイブの使い方

クリップには必ず **問い** が付いています。問いに答えないと、視聴が記録されません。

理由：動画を見るだけでは伸びるという証拠がないからです。
一方で「構造化された視聴ガイド」付きの研究は多数あります（レビューでは77%が使用）。

**答えは短くていいです。** 「02:14 の言い直しだと思います」で十分です。

## 6. セーフガーディング

**1件でも起きたら、全事業を止めて公表します。** 事業KPIより上です。

1. `#/kill` を開く
2. 「何が起きたか」に、いつ・どこで・誰に・何が起きたかを書く（憶測は書かない）
3. 記録すると、**その場でシステムの全機能が止まります**
4. 対応と公表が終わるまで、再開しません

**迷ったら記録してください。** 記録して止まるコストより、記録しなかったコストのほうが桁で大きいです。

---

## 6.5 データを外に出すとき

`#/export`（書き出し）から CSV を保存できます。Excel でそのまま開けます（文字化けしません）。

| よく使うもの | 何のため |
|---|---|
| `scores_wide` | 授業ごとの観点と信号。R / Stata / Python での解析 |
| `irr_pairs` | 評価者間一致を外部で再計算する |
| `mentor_logs` | メンター単価の計算 |
| `survey_responses` | アンケートの分析（**子どもの識別子は入りません**） |

書き出した記録は `auditLog` に残ります。

## 7. 資料に数字を出すとき

1. `#/` の画面で、その数字に **バッジ** が付いているか見る
   - 🟢 検証済み … 一次資料で確認済み。対外説明に使ってよい
   - ⚪️ 自社値 … 裏取り前。**「自社集計」と明記**しないと使えない
   - 🟡 未検証 … 「未検証」と書くなら使ってよい
   - 🔴 エビデンスなし … 使わない

   **緑は「研究がそう言っている」であって「当社がそれを達成した」ではありません。**
   たとえば IRR の目標 .65 の根拠（MET の .67）は緑ですが、当社の実測値は別物です。
2. デモバーが出ているときは、**その画面のスクリーンショットを資料に貼らない**
3. 新しい数字を使うときは、先に `00_はじめに/04_数字の出典一覧.md` に追記する

> 検証済みと未検証を混ぜた瞬間に、検証済みの部分まで信用されなくなります。

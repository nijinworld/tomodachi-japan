# エンジニア引き継ぎ書 ｜ Ranius日本語

株式会社NIJIN ／ 2026年8月 ／ 対象：このコードを引き継ぐ人

読む時間：15分。**最初の3章だけでも読んでください。** 3章を読まずにスコアの計算を変えると、

## 0. これは何か

オンライン日本語スクール **ともだちじゃぱん**（L2）の運用システムであり、
同時に **教師トレーニングシステム Ranius**（L1）の測定器です。

一言でいうと：

> **メンター1人が何人のファシリテーターを支えられるかを、実測するための装置。**

売上でも生徒数でもありません。事業計画のすべての論拠が、この一つの数字に載っています
（→ `01_事業計画/01_事業計画_教師トレーニングシステム【現行】.md` 6.1）。

### 動かす

```bash
node scripts/seed.js                       # デモデータを作る（既存データは消えます）
node server/index.js                       # http://localhost:5173
node scripts/set-passcode.js --list        # 誰がいるか／合言葉が設定済みか
node scripts/set-passcode.js <ID> <合言葉>  # ログインできるようにする
npm test                                   # テスト（件数は実行して確認）
```

デモデータの合言葉は全員 `ranius-demo-2026` です。**実データの前に必ず入れ直してください。**

Node 18以上。**npm install は不要です。依存パッケージはゼロです。**

⚠️ **サーバはデータをメモリに載せています。** `scripts/seed.js` やファイルを直接いじったあとは、
必ずサーバを再起動してください。起動したままだと、古い内容を返し続けます。

## 1. 依存を足す前に読むこと

このコードには外部パッケージが1つも入っていません。理由は3つです。

1. 引き継ぐ相手が、必ずしも Node に詳しくない
2. Google Drive 上のフォルダから、そのまま動く必要がある
3. 12月のA/Bで「同じコードを再実行したら同じ結果が出る」ことを保証したい

**足していいもの**：本番データベースへの移行時のドライバ、認証ライブラリ。
**足す前に相談すること**：スコア計算に関わるもの全部（形態素解析器、ML ライブラリ、LLM SDK）。

形態素解析器を入れたくなったら、それは正しい直感です。ただし **入れた瞬間にモデル版が変わります**。
入れる場合は 3章の手順を踏んでください。

## 3. スコアの仕組み（ここが本体）

### 3.1 3段
```
書き起こし  →  信号(signals)  →  指標(0..1)  →  帯(0..4)
             transcript.js     scoring.js    rubric.ja.json
```

- **信号**：数えられるものだけ。発話比、モーラ数、待ち時間の中央値、取り込み率、ジニ係数など
- **指標**：信号を重みづけて 0〜1 に畳む。`scoring.js` の `INDICATORS`
- **帯**：`rubric.ja.json` の `bands` で 0〜4 に落とす。**しきい値はコードにない**

### 3.2 観点は6つ。うち1つは人間評定が主

| コード | 観点 | 誰が採点するか |
|---|---|---|
| CI | 理解可能なインプットの調整 | AI |
| TD | 発話機会の配分 | AI |
| CF | 訂正フィードバックと取り込み | AI |
| NM | 意味交渉 | AI |
| SC | 足場と安心 | AI |
| **OUT** | **アウトプットの質と変容** | **人間**（AIの値は補助。**AIの平均には入れない**） |

`rubric.ja.json` の各観点に `rater` があります。`rater: "human"` の観点は、
`scoreLesson()` の `overall` から除外され、AIは所見も書きません
（測れないものについて「次の1手」を出すのは、根拠のない指示になるため）。

そのほかに、**点数化しない指標**が1つあります ——「**ともだち（所属感）**」。
子どものアンケートでのみ測り（`spec/survey.ja.json` の `non_scored`）、
先生の評価には混ぜず、時系列で見るだけにします。ともだちじゃぱんの中核指標です。

### 3.3 決めごと（変えるときは全部読んでから）

**① LLM はスコアを出さない。**
LLM が出すのは所見の文面だけです。スコアは決定的な計算で出します。
理由：「モデルを凍結した」と言うには、同じ入力から同じ出力が出なければならないからです。
温度0でも LLM の出力は完全には固定できません。ここを崩すと、事前登録した試験が成立しません。

**② スコアには必ず時刻つきの根拠を付ける。**
根拠なしのスコアは保存しません。これは技術的な都合ではなく、事業の約束です
（「性格に触れない。『熱意が足りない』ではなく『07:22 で指名が4回続いた』」）。

**③ ファシリテーター間の順位を作らない。**
`GET /api/lessons?sort=...` は **403** を返します。消さないでください。
アーム単位の集計だけは許可しています（A/B検証に必要なため）。

**④ 冒頭15分だけを見る。**
`rubric.ja.json` の `window.minutes`。全体の約6割の信頼性が、1/3の時間で出るからです（MET Project）。

### 3.4 モデル版（凍結）

**モデル版 ＝ LLM ＋ プロンプト ＋ ルーブリック の組。1文字変えたら別の版です。**

指紋は `sha256(scorer_version + llm + sha256(rubric.ja.json) + sha256(prompts/feedback.ja.md))`。

```bash
node scripts/freeze-model.js "v2" "何を変えたか"   # 凍結
curl -X POST localhost:5173/api/rescore -d '{}'    # 凍結版で全授業を再スコア
```

**やってはいけないこと：rubric を変えて、古いスコアと新しいスコアを同じグラフに載せる。**
画面はモデル版が混ざると警告を出しますが、警告を無視して資料に貼ることはできてしまいます。

### 3.5 いまの弱点（正直に）

| 何が弱いか | どうなっているか | いつ直すか |
|---|---|---|
| 形態素解析をしていない | モーラ数は近似（漢字＝2モーラ）。リキャストは文字バイグラムの重なりで判定 | 精度が問題になったら。ただし版が変わる |
| ルーブリックが未検証 | 因子分析・クロスウォークとも未実施 | 1,000授業がたまってから |
| 観点が天井/床に張りつく | `/api/analysis/instrument` が検出する。SC観点は現に張りついている | IRR測定と同時に記述語を直す |
| 音声からの書き起こしがない | 書き起こしは外から入れる前提（`POST /api/lessons`） | 文字起こしの調達が決まってから |
| 音声を自動で文字にしない | 会議ツールが出した書き起こしを貼り付ける前提 | 文字起こしの調達が決まってから |
| 通信が暗号化されていない | HTTP。合言葉が平文でネットワークを流れる | **社外から使う前に HTTPS 必須**（6章） |

## 4. データ

`data/*.json` に素で置いています。1コレクション＝1ファイル。書き込みは一時ファイル＋rename。

| ファイル | 中身 | 目安の増え方 |
|---|---|---|
| `utterances.json` | 発話。いちばん大きい | 1授業 ≒ 250発話 |
| `scores.json` | AIスコア。`signals` と `events` を丸ごと持つ | 授業×モデル版 |
| `mentorLogs.json` | **メンターの毎日1行。事業の全論拠** | 人×日 |
| `ratings.json` | 人間評定者の盲検採点 | サブサンプルのみ |

**データベースに移すとき**（8章）は、`lib/store.js` の `all/find/get/insert/update/remove` だけを
差し替えれば動きます。他のコードは store の中身を知りません。

移行先の叩き台として **`spec/schema.sql`（PostgreSQL）** が入っています。以前の設計から引き継いだもので、
「有効なモデル版は常に1つだけ」といった不変条件を DB 制約として表現しています。
いまのコードはこのスキーマでは動きません（JSONストアのままです）。**設計の参照用**として読んでください。

## 5. 構造として禁止していること

コードで機械的に止めています。仕様変更の依頼が来ても、**事業計画側の合意なしに外さないでください。**

| 何を | どこで | 返す |
|---|---|---|
| 先生の順位づけ | `routes/api.js` の `/api/lessons` | 403 RANKING_FORBIDDEN |
| 人格に触れる所見 | `lib/ja.js` の `PERSONALITY_TERMS` | 422 PERSONALITY_TERM |
| 問いのないアーカイブ視聴 | `/api/clips`, `/api/clips/:id/view` | 400 |
| 回答4件未満のアンケート返却 | `lib/survey.js` | 集計を返さない |
| 公表日なしの事案クローズ | `/api/incidents/:id/close` | 400 |
| セーフガーディング事案が開いている間の全操作 | `routes/api.js` の `handle()` | **423 HALTED** |
| 評定者が授業・クリップ・週次・事案に触れる | 各ルートの `roles` | 403 |
| 先生が他人のアンケート・チーム・所見に触れる | `canSeeFacilitator` / `visibleTeams` | 403、または結果から除外 |
| 先生が「メンターの所見」を自作する | `/api/feedbacks` | 403（担当数が動くため） |
| body で身元を名乗る（`raterId` / `userId` / `facilitatorId`） | 各ルート | セッションの本人に固定 |
| アンケート回答に子どものIDを保存する | `/api/surveys/responses`, `/api/survey/:token` | 400、または常に `null` |
| 子ども用アンケートの部分回答・連投 | `/api/survey/:token` | 400 ／ 429（名簿+4件で打ち止め） |
| 同意のない子どもの発話を保存する | `/api/import/lesson` | 400 CONSENT_REQUIRED |
| デモのCSVをデモと分からない形で出す | `/api/export/:id` | ファイル名と先頭行に DEMO を入れる |

**これらは2026-08-18の内部監査で見つかった穴です。** テストで固定してあります（`test/run.js` の「監査：」で始まる13件）。
外すときは、なぜ外すのかを先に書いてください。

最後の1つは強い挙動です。事案を1件記録すると、確認と記録以外のAPIが全部止まります。
Bridge International の教訓（成果は良かったが、姿勢で潰れた）をコードに落としたものです。

## 6. 認証とロール

### 6.1 しくみ

- 合言葉は **scrypt** でハッシュ化して `users` に持つ。平文はどこにも残らない
- ログインすると **署名つきクッキー**（HttpOnly／SameSite=Strict／12時間）を返す
- 「自分は誰々です」と名乗れる経路は作っていない。**ヘッダもクエリも見ない**（`server/index.js`）
- 秘密鍵は初回起動時に生成して `data/settings.json` に入る

合言葉の設定は `node scripts/set-passcode.js <ID> <合言葉>`、または画面の「人とクラス」から。

### 6.2 ロールと見えるもの

> **設計の急所：一覧を返すエンドポイントは、必ずサーバ側で絞ること。**
> 画面側で `filter` するだけだと、データはブラウザまで届いています。
> 監査で見つかった穴の半分がこれでした。

| ロール | 見えるもの | 見えないもの |
|---|---|---|
| **admin** | 全部 | — |
| **mentor** | 担当チームの先生の授業・所見・記録、集計 | 担当外の先生 |
| **facilitator** | **自分の授業・所見・アンケートだけ** | 他の先生、A/B、費用、アーカイブの効果分析 |
| **rater** | **盲検の採点キューだけ** | 先生の名前、アーム、AIスコア、子どもの名前、授業一覧 |
| **staff** | 費用・設定・書き出し | 授業の中身 |

**rater の遮断がいちばん大事です。** ここが漏れると IRR が「AIに引っぱられた一致」になり、
測る意味がなくなります。`/api/blind/*` 以外から授業に到達できないことを、テストで固定しています。

### 6.3 子どもの仮名化

- `students.id` に名前を入れない（`st_0_0`）。名前は `students.name` に分離
- 名前を返すかどうかは `auth.canSeeChildNames()` が決める。rater には常に「子ども1」
- **アンケートの回答に `studentId` を残さない**（`POST /api/survey/:token` は常に `null`）。
  誰が何と答えたかを、こちら側で分からなくするためです
- CSV書き出しにも子どもの識別子は出ません（`server/lib/export.js`）

### 6.4 保護者の同意

**同意のない子どものことばは、そもそも保存しません。**

- `students[].consent = { obtainedAt, by, method, note, recordedBy, withdrawnAt? }`
- 取り込み時に確認し、同意のない子が名簿にいると **400 CONSENT_REQUIRED** で止まる
- 確認するかどうかは設定 `require_consent`（既定 true）。**実データでは true のままにすること**
- 撤回されたら、以降は取り込めない。すでにある分は `node scripts/purge.js --student <ID>`

配布用の説明文のひな型が `docs/保護者への説明.md` にあります。
**システムの動きを変えたら、あの文も直してください。** 食い違ったまま配るのがいちばん問題です。

### 6.5 保存期間と削除

`transcript_retention_days`（既定180日）を過ぎた授業について、**子どものことばだけ**を消します。

| 消す | 残す |
|---|---|
| 発話（`utterances`） | スコア、信号（数値）、時刻、イベントの種類 |
| スコア・所見に引用された本文 | 「何点だったか」を説明できる材料 |

```bash
node scripts/purge.js --dry-run     # 何が消えるか見る
node scripts/purge.js               # 消す
node scripts/purge.js --student <ID>  # 同意を撤回した子のことばだけ
```

**画面からは実行できないようにしてあります。** 消したものは戻らないので、意図して端末で叩く形にしています。
状況は `#/records`（保存と閲覧の記録）で見えます。

### 6.6 閲覧の記録

`auditLog` に残るもの：ログイン（成功・失敗）／**書き起こしを開いた**（`lesson.transcript.view`／`blind.transcript.view`）／
書き出し／合言葉の設定／同意の記録と撤回／事案／purge。
`#/records` で運営が見られます。「誰がいつ見たか」を保護者に説明できる状態を保つためのものです。

### 6.7 バックアップ

```bash
node scripts/backup.js --keep 30    # 控えて、30世代より古いものを消す
node scripts/backup.js --list       # いままでの控え
```

Windows なら `毎日の控え.cmd` をタスクスケジューラに毎日1回登録してください（手順はファイル内のコメント）。
復元はサーバを止めて、控えの中身を `data/` に戻すだけです。

### 6.8 それでも残っていること

1. **HTTPS**：`certs/key.pem` と `certs/cert.pem` を置く（または `RANIUS_TLS_KEY` / `RANIUS_TLS_CERT`）と
   自動で HTTPS になり、クッキーに `Secure` が付きます。**証明書の調達はまだです。**
   社内LANの外から使うなら、証明書を用意するか、リバースプロキシで TLS を張ってください
2. **同意書の実物の保管**：システムに残るのは「いつ・誰から・どの方法で得たか」の記録だけです。
   書面そのものの保管場所は別に決めてください
3. **保存期間の自動実行**：`purge.js` は手で叩く前提です。自動化するかは、運用が固まってから決めてください

## 7. 撤退基準（この章は消さないでください）

**判断のときに基準を作ると、必ず自分に甘くなります。** だから先に書いてあります。
実体は `spec/kill-criteria.json`、画面は `#/kill`。

| # | 何が起きたら | どうするか |
|---|---|---|
| 0 | **セーフガーディング事案が1件でも起きたら** | **全事業を止めて公表する。**システムも止まる |
| 1 | 在校生（不登校の子）の満足度・出席が1ptでも落ちたら | 即停止。事業KPIより上 |
| 2 | メンター担当数がA比で3倍未満のままなら（18か月） | 律速はAIコーチではない。別の律速を探す |
| 3 | B群の質がA群の80%に届かないなら | Raniusは「代替」ではなく「補助」。中核主張を書き換える |
| 4 | 保護者の解約率のA/B差が5ptを超えたら | 実験を止める |
| 5 | **10月20日までにIRRが .65 に届かなければ** | ルーブリックが機能していない。器具を直す |
| 6 | 採用率が2%から動かないなら | 訓練システムではなく採用フィルター。前提が崩れる<br>**※ いまは判定していません**（`spec/kill-criteria.json` の `enabled: false`）。この数字が `00_はじめに/04_数字の出典一覧.md` に無いためです。出典表に載って裏が取れたら `true` に戻してください |

しきい値をコードに直接書いていないのは、**あとから静かに動かせないようにするため**です。
`spec/kill-criteria.json` の変更は差分に残ります。
